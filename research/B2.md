# B2. Usage sources compared on exact samples

Spike for the audit (docs/spec/audit.md), step B2. Question: which source should count tokens and cost per assignment, trace and session? Four candidates were compared on the same inputs:

1. **Own reader.** `research/audit_reader.py`: stdlib, dedup `(message.id, requestId)` first-wins with the earliest file first, conflicts and `no_key` rows counted.
2. **claude-cost-tracker.** Pinned at `bb5eb9f`, read-only clone, run as `python3 -m claude_cost_tracker --all --json` with `CLAUDE_CONFIG_DIR` pointing at a **copy** of the inputs, `CCOST_NO_CACHE=1`, and a private `HOME`/`CCOST_HOME`.
3. **Claude Code's own `cost-state` rows.** These are already in every transcript (2.1.322): a per-session counter `modelUsage` plus `totalCostUSD`.
4. **Local OpenTelemetry.** `CLAUDE_CODE_ENABLE_TELEMETRY=1` with the console exporters, measured on one tiny real `claude -p` run.

Samples:

- **F.** The step A usage fixture: 3 files, 7 assistant rows, 4 unique exchanges, of which one file is a fork copy.
- **R.** A frozen copy of one operator's 44 professional-session transcripts (read 2026-11-12 16:05 UTC). It holds 3,128 assistant usage rows, of which 2,239 repeat a key. Step A read 3,015 / 2,167 earlier the same day; the sessions were still running. Only counts are reported here.
- **O.** One 1-request real session with OTel on.

Token order everywhere: input / output / cache write / cache read.

## Results

### F: the usage fixture (expected: 250 unique; assignments 140 + 80; session-only 30; fork copy 0)

| Source | Exchanges | Tokens | Per-scope | Notes |
|---|---|---|---|---|
| Own reader | 4 | 120 / 80 / 20 / 30 = **250** | root 140, child 80, inclusive 220, session-only 30 | 3 duplicate rows, 0 conflicts. Exact |
| Tracker `--all` | 6 turns | 190 / 110 / 20 / 60 = **380** | per session only: 80, 170, **130 (the fork copy)** | Overcounts by 130 (52 %) |
| Tracker `--session <id>` | 1 / 3 / 2 | 80 / 170 / 130 | session only | No assignment split |

Why the tracker overcounts: its `dedup_turns` is cross-file, but `analyse.py:109` calls it per transcript (`dedup_turns([parsed])`). Copies across files (fork, resume into a new file) are therefore summed again under `--all`. Its JSON carries no `message.id`/`requestId` per turn, only `(session_id, ordinal)`, and turn `components` are cost micros, not tokens. So it cannot be joined at the request level, and per-assignment attribution is impossible from its output.

### R: real transcripts (44 sessions, one model)

| Source | Exchanges | Tokens (in / out / write / read) | Total | API-equivalent cost |
|---|---|---|---|---|
| Raw rows, no dedup | 3,128 | 6,384 / 6,456,916 / 41,662,007 / 483,162,027 | 531,287,334 (3.01x) | — |
| Own reader | 889 | 1,834 / 2,377,562 / 9,191,030 / 164,854,456 | **176,424,882** | $77.028854 (pinned table, see below) |
| Tracker `--all` | 889 turns | 1,834 / 2,377,562 / 9,191,030 / 164,854,456 | **176,424,882** | $77.028834 (same table, via `CCOST_PRICING`) |
| `cost-state` (last row per session) | — | 60,827 / 2,398,802 / 9,228,507 / 184,959,123 | 197,647,259 | $79.519112 (Claude Code's own) |

- Own reader and tracker agree exactly on tokens. Cost differs by 20 micro-dollars because of per-turn rounding. There are 0 usage conflicts, 0 `no_key` rows and 0 cross-file copies in R, which is why the tracker bug does not show here.
- **The tracker refuses to run (exit 2, no output) when a model is missing from its rate table.** Its bundled table (priced 2026-08-11) lacks the model in R, so a table had to be supplied. Unknown model → no numbers at all, where the brief's rule is tokens counted, cost `unpriced`.
- The tracker output is stable. Two runs gave the same JSON hash once `generated_at` was dropped.
- **`cost-state` is larger than the transcripts by 21,222,377 tokens (12.0 %; 37 of 44 sessions differ, 7 equal).** It is a session counter that also counts requests never written as assistant rows. Evidence: there are 893 `api-request` rows (`repl_main_thread`) against 889 assistant keys, and side requests are not in the file at all. It holds only one model here. It cannot be joined per request, but it measures the per-session residual that transcripts cannot see.
- 1h cache writes: all 9,191,030 write tokens in R carry `ephemeral_1h`. A 5m-only price would understate write cost by 37.5 %, so the split must be read from `usage.cache_creation`.

### O: local OpenTelemetry, one request

`claude_code.api_request` event attributes: `request_id`, `session.id`, `prompt.id`, `model`, `input_tokens` 2, `output_tokens` 4, `cache_read_tokens` 11,382, `cache_creation_tokens` 10,503 (`cache_creation_1h_tokens` 10,503), `cost_usd` 0.00221662, `duration_ms`, `ttft_ms`.

The transcript row with the same `requestId` has exactly 2 / 4 / 10,503 / 11,382. The pinned table gives $0.0022166 for it, equal to Claude Code's own `cost_usd`.

What else OTel showed:

- Every OTel record carries `user.email`, `user.account_uuid` and `organization.id` (18 occurrences in this one run). These must never be stored.
- The console exporter writes to the session's stdout, which would corrupt a TUI session. OTLP needs a local receiver.
- It is off by default and must be enabled per session through the environment.

## Pricing

The table is pinned and dated in the repo: one row per model, with input and output USD/MTok, the cache-read multiplier (per model where it differs), and the 5m and 1h write multipliers.

Unknown model → tokens counted, `cost=null`, `priced=false`, and an unpriced share shown. Every cost is labelled API-equivalent.

The tracker's table format (schema v1 TOML) is a good interchange shape. A stdlib core cannot parse TOML before 3.11, so the core ships JSON. An optional check can compare it with a tracker table.

## Decision for C

| Choice | Decision | Why (evidence above) |
|---|---|---|
| Core usage source | **Own stdlib reader** over transcripts. Dedup `(message.id, requestId)` first-wins, earliest file first. Conflicts and `no_key` rows counted and shown | Exact on F and R. It joins per request (needed for assignment attribution). Stdlib only |
| Session residual | **`cost-state` counter minus transcript sum, per session**, labelled "session counter, not request-level" | The only local source of the 12 % of usage that transcripts lack. Already on disk, no opt-in |
| Tracker | **Optional cross-check adapter only** (never imported by the core), run on a copy. Compare session totals; never use it for attribution | No request ids, per-file dedup overcount, hard failure on unknown models, needs 3.12 + Rich |
| OpenTelemetry | **Not in the first release.** Optional later source behind an explicit setting, needing a loopback OTLP receiver. Joins on `request_id` == transcript `requestId`; only allowlisted attributes are kept | Exact per-request numbers including `duration_ms`. But it carries personal identifiers, needs a receiver, and is off by default |
| Accounting | Tokens per category from the provider. Cost derived from the pinned table, 1h vs 5m writes from `cache_creation` | 1h writes dominate R |

## Unresolved

- Resume/fork row copying on real 2.1.322 data: no real resumed or forked professional session exists locally (B1). The fixture covers the shape. The first real resume after D1 should be checked with `audit_reader.py --counts-only`, which reports `dup_rows` across files.
- When `cost-state` is written: R has exactly one row per session file. Whether a resumed session restarts or continues the counter is unknown. Until checked, the residual is reported per transcript file.
- The usage reports of other Claude Code versions and models: R is one version and one model.
- The tracker's attribution (per file/folder) is not evaluated. It answers a different question (context cost by item), which could serve a later "context sources" card.
